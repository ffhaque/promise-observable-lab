DECISION GUIDE

What shape is your async work?

STARTONE EVENTUAL RESULT?
YESCAN CONTEXT CHANGE?Yes → Observable + switchMap
No → Is it a simple linear flow?
NOVALUES OVER TIME?Yes → Observable
No → choose the clearest composition
PROMISESimple, linear, one-shot work
OBSERVABLEChanging context, repeated values, owned lifecycle

PROMISE

  • One eventual result
  • Sequential one-shot work
  • Simple commands
  • Promise.all for fixed parallel work

OBSERVABLE

  • Values over time
  • Latest-only behavior
  • Changing context and event shaping
  • Reactive composition and lifecycle ownership

EITHER

  • Both model the task well
  • Choose readability
  • Follow the surrounding API
  • Do not treat timer noise as a winner
CAPABILITYPROMISEOBSERVABLE
1. One async resultExcellent and simpleAlso excellent
2. Latest result mattersManual identity + cancellationswitchMap disposes obsolete work
3. Context changes mid-workflowOld workflows need manual coordinationswitchMap disposes the whole workflow
4. High-frequency eventsManual event shapingOperators shape before expensive work
5. Multiple changing sourcesExcellent one-time snapshotcombineLatest maintains a live view
6–10. Reactive workflowsPossible with explicit coordinationDeclarative cancellation, fallback, streams, cleanup
11. Simple saveBest fit: direct async/awaitValid, but extra machinery
12. Sequential one-time workflowNatural top-to-bottom control flowUseful when the workflow must become a stream
13. Parallel one-time requestsPromise.allforkJoin

Observable is not inherently faster than Promise.

Observable becomes powerful when time, cancellation, repeated values, changing context, or composition are part of the problem.

DON'T ASK: “WHICH ONE IS BETTER?”Ask: “What is the shape of my asynchronous problem?”
