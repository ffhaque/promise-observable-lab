DECISION GUIDE

WHAT SHAPE IS YOUR ASYNC WORK?

STARTONE EVENTUAL RESULT?
YESCAN CONTEXT CHANGE?Yes → Observable + switchMap
No → Is it a simple linear flow?
NOVALUES OVER TIME?Yes → Observable
No → choose the clearest composition
PROMISESimple, linear, one-shot work
OBSERVABLEChanging context, repeated values, owned lifecycle
WORK MUST STOP WITH COMPONENT?YES → Observable lifecycle / teardown

PROMISE

  • One eventual result
  • Sequential one-shot work
  • Simple commands
  • Promise.all for fixed parallel work

OBSERVABLE

  • Values over time
  • Latest-only behavior
  • Changing context and event shaping
  • Reactive composition and lifecycle ownership

BOTH

  • Simple one-shot work
  • Both model the task well
  • Choose whichever communicates intent best
  • Do not treat timer noise as a winner
CAPABILITYPROMISEOBSERVABLE
1. Baseline requestBoth Are GoodBoth Are Good
2. Search under loadObsolete work keeps its laneObservable Advantage
3. Rapid selection workflowVersion guard; old work continuesObservable Advantage
4. Live dashboardPoint-in-time snapshotContinuing synchronized view
5. Component cleanupExternal cancellation requiredObservable Advantage
6. Sequential workflowPromise AdvantageCorrect, but more machinery

Observable is not inherently faster. Use Promise when a simple one-shot async flow is all you need.

Observable becomes powerful when time, changing context, repeated values, or lifecycle are part of the problem.
